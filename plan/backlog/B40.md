# B40: The Arlington model gives AnnotSquare `/CA` from PDF 2.0

Status: open

- **Found:** 2026-10-24, the Arlington checks (F22)
- **Where:** the model pdf-lint 0.1.0 embeds,
  `model/tsv/latest/AnnotSquare.tsv` (upstream's at `d148fee`, which
  its `corrections.tsv` doesn't correct); upstream's `tsv/1.7`
  AnnotSquare has no CA
- **Severity:** annoyance (an error in the model)
- **What happens:** a Square mark's `/CA` in a file below 2.0 is a
  `too-new` finding.
- **Expected:** `/CA` from 1.4. ISO 32000-1 Table 170 gives every markup
  annotation `/CA` from 1.4, Table 169 makes Square one, and AnnotCircle,
  Square's twin in Table 177, has it from 1.4.
- **Repro:** `every_mark_kind_holds` without the allowance row
- **Notes:** held by `AnnotSquare CA too-new` in
  `crates/sheaf-ops/tests/arlington_allowed.tsv`, which
  `every_mark_kind_holds` needs. A candidate for pdf-lint's
  `corrections.tsv` (Greg's to make, as pdf-lint is his), which would
  close this entry and the row; worth reporting to
  pdf-association/arlington-pdf-model too, a public report, so Greg
  approves it first.
