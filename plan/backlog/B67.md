# B67: A Rewrite to another file can lose a block's text without saying so

Status: open

- **Found:** 2026-10-27, Claude, during the gpui-pre 0.3.10 bump (`just
  precommit`'s `properties`)
- **Where:** the property `append_rewrite_reopen_alike_1024`
  (`crates/sheaf-doc/src/materialize/append_rewrite_tests.rs:616`, in
  `planned`): the save plan's `Strategy::Rewrite` and
  `removal::of_rewrite`
- **Severity:** wrong output (unless the property's check is what's wrong)
- **What happens:** a Rewrite planned only because the target is another
  file (`why: [OtherTarget]`) loses derived text: `removal::of_rewrite`
  finds `Found { key: Block(…), derived: true, said: false }`, though the
  plan says nothing is removed or replaced.
- **Expected:** a Rewrite that removes nothing keeps every derived
  object's text, or its plan says why not.
- **Repro:** add this line to
  `crates/sheaf-doc/proptest-regressions/materialize/append_rewrite_tests.txt`
  and run `scripts/test-capped.sh cargo test -p sheaf-doc --release --lib
  -- --ignored append_rewrite_reopen_alike_1024`; it fails on the replayed
  case:

  ```
  cc 48bf2b66df422acd08cda7662aa9d1673b7883b29a80d09c2e3104e60fa98570 # shrinks to xfa = false, marked = false, actions = [(25, 10998018234546696428), (0, 9711464738867046170), (4, 15343248506831901426), (22, 11425878001022480198), (32, 0), (2, 4688869470783777387), (0, 768304061419315557), (0, 0), (39, 0)]
  ```
- **Notes:** on main: the bump changed neither sheaf-doc nor anything it
  depends on, and the replay fails the same way. Random cases found it;
  the same 1,024-case run passed in earlier precommits. Not looked into:
  which of the actions loses the text, and whether `of_rewrite` is right
  that it's gone.
